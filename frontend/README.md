# Sync-Up Frontend

This directory contains the client application for Sync-Up, built with React, Vite, Tailwind CSS, and React Router.

The frontend is responsible for:
- Public entry experience (landing and authentication flows)
- Role-aware registration onboarding
- Main product navigation pages (home, network, events, opportunities, etc.)
- Client-side routing and UI rendering
- Styling system and reusable visual utilities

## Technology Stack

- React 18
- React DOM 18
- React Router DOM 6
- Vite 5
- Tailwind CSS 3
- PostCSS + Autoprefixer

## Frontend Architecture Overview

### 1) Entry and Render Pipeline

- `src/main.jsx` is the application entry point.
- It mounts React into `#root` and wraps the app in `React.StrictMode`.
- `src/App.jsx` currently owns route declarations.

### 2) Routing Layer

- Routing uses `BrowserRouter`, `Routes`, and `Route` from React Router.
- All route definitions are currently centralized in `src/App.jsx`.
- `src/routes/AppRoutes.jsx` exists and is currently empty, likely intended for future route modularization.

### 3) Page Layer

- Pages are organized under `src/pages`.
- Authentication-related pages are grouped under `src/pages/Auth`.
- Top-level app pages are grouped as peers in `src/pages`.

### 4) Styling Layer

- Tailwind directives are loaded in `src/index.css`.
- Global CSS reset and utility classes are declared in `src/index.css`.
- Design tokens and custom animations are configured in `tailwind.config.js`.

### 5) Build and Dev Server

- Vite handles development server and production build.
- Current Vite dev server config:
  - Port: `5173`
  - Browser auto-open: enabled

## Getting Started

From the `frontend` directory:

```bash
npm install
npm run dev
```

Then open:

- `http://localhost:5173`

Because `open: true` is enabled in Vite config, your default browser should open automatically.

## Available Scripts

### `npm run dev`
Starts Vite development server with hot reload.

### `npm run build`
Creates an optimized production build in the output directory generated by Vite.

### `npm run preview`
Runs a local server to preview the production build.

## Typical Development Workflow

1. Create or update page components in `src/pages`.
2. Register/adjust route definitions in `src/App.jsx`.
3. Apply styling with Tailwind utility classes and shared CSS helpers.
4. Run `npm run dev` for iterative development.
5. Run `npm run build` before opening merge requests.

## Conventions and Recommendations

- Keep each page focused on one screen responsibility.
- Move reusable UI sections into dedicated components when duplication appears.
- Prefer Tailwind utilities first; use global CSS for shared patterns and advanced effects.
- Keep route names human-readable and stable once shared externally.
- Validate route-level navigation manually after route changes.

## Integration Notes (Monorepo Context)

This frontend exists inside a larger workspace with multiple backend services (identity, profile, events, notifications, promotions, and gateway).

When API wiring is added or expanded:
- Centralize API base URL configuration (for example through environment variables).
- Keep request clients and endpoint modules separate from UI components.
- Avoid hardcoding service URLs directly in page files.

## Environment Variables

No frontend-specific `.env` variables are required at this moment based on current configuration.

If environment-specific API configuration is introduced, follow Vite conventions:
- Prefix client-exposed vars with `VITE_`.
- Access via `import.meta.env`.

Example:

```env
VITE_API_BASE_URL=http://localhost:4000
```

```js
const apiBaseUrl = import.meta.env.VITE_API_BASE_URL;
```

## Troubleshooting

### Port already in use

If `5173` is occupied:
- Stop the existing process using that port, or
- Change port in `vite.config.js`.

### Module resolution/build issues

```bash
rm -rf node_modules package-lock.json
npm install
npm run dev
```

On Windows PowerShell:

```powershell
Remove-Item -Recurse -Force node_modules
Remove-Item -Force package-lock.json
npm install
npm run dev
```

### Tailwind classes not applying

- Ensure `src/index.css` contains Tailwind directives.
- Verify `tailwind.config.js` content paths include your JSX/TSX files.
- Confirm `index.css` is imported in `src/main.jsx`.
